# Xray VLESS Server for Ubuntu

Автоматическая установка собственного VLESS-сервера на Ubuntu с транспортом **XHTTP** и защитой **REALITY**.

Проект рассчитан на собственный VPS и предназначен для подключения к нему с Xray-клиентов. Секретные параметры сервера генерируются непосредственно на сервере и не должны попадать в Git.

## Что устанавливается

- Xray-core из официального установщика Xray
- VLESS inbound на TCP/443
- XHTTP transport
- REALITY
- systemd service Xray
- автоматическая генерация UUID, REALITY key pair и shortId
- UFW rule для TCP/443, если UFW уже активен
- VLESS URL и JSON-параметры клиента

## Требования

- Ubuntu 24.04 или новее
- VPS с публичным IPv4
- root/sudo
- свободный TCP-порт 443

## Установка

```bash
git clone https://github.com/xalexey77-hub/xray-vless-server.git
cd xray-vless-server
sudo bash install.sh
```

Установщик спросит:

1. `REALITY serverName` — имя хоста, соответствующее сертификату целевого TLS-сервера.
2. `REALITY destination` — адрес целевого TLS-сервера, например `www.example.com:443`.
3. `XHTTP path` — путь XHTTP, например `/xhttp`.

После установки скрипт покажет VLESS URL. Его можно импортировать в клиент, поддерживающий VLESS + XHTTP + REALITY.

## Быстрое управление пользователями

Все команды выполняются на сервере из каталога проекта:

```bash
cd /root/xray-vless-server
```

### 1. Добавить пользователя

Например, создать пользователя `Ivan`:

```bash
sudo bash scripts/add-user.sh Ivan
```

Или:

```bash
sudo bash scripts/add-user.sh friend1
```

Скрипт автоматически:

1. генерирует отдельный UUID;
2. добавляет пользователя в VLESS inbound на TCP/443;
3. сохраняет резервную копию текущей конфигурации;
4. проверяет новый JSON через Xray;
5. устанавливает конфигурацию;
6. перезапускает Xray;
7. проверяет, что Xray успешно запущен;
8. формирует готовую VLESS-ссылку;
9. сохраняет её в `/etc/xray-vless/users/<имя>.txt`.

### 2. Получить список пользователей

```bash
sudo bash scripts/list-users.sh
```

### 3. Получить VLESS-ссылку пользователя

```bash
sudo cat /etc/xray-vless/users/Ivan.txt
```

### 4. Удалить пользователя

```bash
sudo bash scripts/remove-user.sh Ivan
```

Скрипт удаляет UUID пользователя из VLESS-конфигурации, проверяет конфигурацию, перезапускает Xray и при ошибке выполняет откат.

### 5. Проверить состояние Xray

```bash
sudo bash scripts/status.sh
```

## Клиенты для подключения

Сервер использует **VLESS + XHTTP + REALITY**, поэтому клиент должен поддерживать именно эту комбинацию.

### Android

**v2rayNG — основной рекомендуемый вариант.** Для подключения достаточно импортировать персональную `vless://` ссылку.

### iPhone / iOS

Для iOS разные приложения используют разные сетевые ядра. Перед использованием необходимо проверить поддержку именно **VLESS + XHTTP + REALITY** в актуальной версии клиента.

### Windows / macOS / Linux

Можно использовать клиенты на базе Xray-core или sing-box, если они поддерживают VLESS + XHTTP + REALITY. Для Windows ранее проверена работа профиля в **v2rayN** с Xray-core.

### Краткая таблица

| Платформа | Клиент | VLESS | REALITY | XHTTP | Рекомендация |
|---|---|---:|---:|---:|---|
| Android | v2rayNG | ✅ | ✅ | ✅ | **Основной вариант** |
| Android | Hiddify | ✅ | ✅ | ⚠️ | Проверять версию |
| iOS | Hiddify | ✅ | ✅ | ⚠️ | Проверять актуальную версию |
| iOS | Streisand | ✅ | ✅ | ⚠️ | Проверять актуальную версию |
| iOS | Shadowrocket | ✅ | ✅ | ⚠️ | Проверять поддержку XHTTP |
| Windows | v2rayN | ✅ | ✅ | ✅ | **Проверено с Xray-core** |

> Таблица является практической рекомендацией для проекта, а не гарантией совместимости каждой версии приложения.

## Безопасность и повышение живучести VPS

Цель этого раздела — уменьшить поверхность атаки и сделать сервер устойчивее к обычным сетевым сбоям и ошибкам администрирования. Это **не является гарантией обнаружения или необнаружения VPN-трафика** и не обещает обход конкретных систем блокировки.

### Базовое hardening

Скрипт `scripts/harden.sh`:

- устанавливает и включает UFW;
- запрещает входящие соединения по умолчанию;
- разрешает SSH TCP/22;
- разрешает Xray TCP/443;
- включает автоматические security updates, если они доступны;
- создаёт резервную копию SSH и Xray-конфигурации;
- проверяет конфигурацию SSH;
- **не изменяет Xray-конфигурацию и не перезапускает SSH автоматически**.

Запуск:

```bash
sudo bash scripts/harden.sh
```

После запуска необходимо проверить SSH-доступ из второго терминала, прежде чем закрывать текущую сессию.

> Перед применением hardening на удалённом VPS убедитесь, что текущий SSH-доступ работает.

### Резервное копирование

Создать локальную резервную копию Xray и связанных данных:

```bash
sudo bash scripts/backup.sh
```

Резервные копии хранятся вне Git-репозитория:

```text
/root/xray-vless-backups/
```

### Восстановление

Восстановить последний backup:

```bash
sudo bash scripts/restore.sh
```

Или указать конкретный каталог:

```bash
sudo bash scripts/restore.sh /root/xray-vless-backups/20260911-120000
```

Перед восстановлением Xray проверяет JSON. При неудачном запуске `xray.service` скрипт пытается вернуть предыдущую конфигурацию.

### Резервный VPS

Для повышения отказоустойчивости рекомендуется иметь второй VPS у другого провайдера или в другой сети. На нём можно заранее установить тот же проект и протестировать конфигурацию.

```text
             Пользователь
                   |
             VLESS profile
                   |
        +----------+----------+
        |                     |
     VPS #1                VPS #2
     Xray                   Xray
     TCP/443               TCP/443
        |                     |
        +----------+----------+
                   |
          резервная инфраструктура
```

При проблеме с одним endpoint администратор может выдать пользователям новую VLESS-ссылку для второго сервера.

### Что не следует делать

Не следует:

- хранить REALITY private key в Git;
- публиковать рабочие VLESS-ссылки в README, Issues или публичных сообщениях;
- менять `serverName`, REALITY key pair или XHTTP параметры на рабочем сервере без резервной копии;
- закрывать текущую SSH-сессию сразу после изменения firewall;
- считать наличие REALITY/XHTTP гарантией от блокировки.

## Проверка

```bash
sudo bash scripts/status.sh
```

Получить основной клиентский профиль повторно:

```bash
sudo bash scripts/show-client-config.sh
```

Логи:

```bash
sudo journalctl -u xray.service -f
```

Проверка конфигурации:

```bash
sudo /usr/local/bin/xray run -test -config /usr/local/etc/xray/config.json
```

## Как передать VLESS пользователю

После создания пользователя получите его ссылку:

```bash
sudo cat /etc/xray-vless/users/Ivan.txt
```

Передайте пользователю строку, начинающуюся с:

```text
vless://
```

Не передавайте содержимое `REALITY private key`. Приватный ключ сервера хранится только на сервере.

## Файлы на сервере

- `/usr/local/etc/xray/config.json` — конфигурация Xray
- `/etc/xray-vless/server.env` — секретные параметры сервера
- `/etc/xray-vless/client.json` — параметры основного клиента
- `/etc/xray-vless/client.txt` — VLESS URL основного клиента
- `/etc/xray-vless/users/` — индивидуальные VLESS-ссылки пользователей
- `/root/xray-vless-backups/` — резервные копии, не входящие в Git

Эти файлы с секретами не должны попадать в Git.

## Удаление

```bash
sudo bash scripts/uninstall.sh
```

Скрипт запросит подтверждение `yes` перед удалением.

## Важно

REALITY/XHTTP не гарантирует работу в любой сети: эффективность зависит от текущих методов фильтрации и блокировок. Перед использованием необходимо убедиться, что выбранный `serverName` действительно соответствует TLS-сертификату и поддерживает необходимые параметры TLS.

Конфигурация проекта намеренно минимальная. Скрипты управления несколькими VLESS-пользователями и базового hardening включены в проект.
